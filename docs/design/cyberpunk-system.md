## Visual direction

Premium engineering editorial: pure-black fields, deep charcoal surfaces, teal and champagne technical accents, restrained crimson highlights, precise mono labels and clear accessible copy. No cyan, teal, purple or rainbow accent system. The README cannot force GitHub's page background; artwork uses a graphite, deep-teal, champagne and ice palette.

## Card architecture

- Six project cards use separate project-specific motion artwork generated from their project studies. The moving scan is a decorative overlay; the README text remains the source of project claims.
- Six Technical Focus cards use six distinct self-hosted images in a two-column table layout. Descriptions remain accessible HTML text.
- Education remains a two-stage completed/current presentation with a timeline artwork.
- Mechanical visualisation retains the existing parametric piston/connecting-rod/crankshaft render. It is a generated mesh study, not a production engine or editable CAD source.
- Analytics use a dated static source snapshot and a separate decorative trace animation. The animation does not change the underlying values.
- All project capabilities and limitations are described in text outside artwork. No unverified live demos or performance claims are added.

## Motion specification

The profile uses distinct self-hosted motion per content type: route-node progression for browser automation, type-on chat for AI, notification ripples for Android, expanding reticles for Circle to Search, vertical document feed for scanner architecture, and playlist equaliser movement for IPTV. Technical Focus uses six separate motion grammars: terminal typing, neural-node activation, notification ripple, piston travel, page-turn/progress, and orbital wireframe. Section titles and key card labels use self-hosted letter-by-letter typewriter loops. The Hero combines typewriter identity text with a rotating rotor. Education uses a sequential timeline reveal; analytics animates the dated values into their fixed totals, not live data.

| Asset family | Frames | Timing | Loop | Purpose |

The GIFs use self-hosted raster frames because README CSS/JavaScript animation and hover effects are unsupported. GitHub's rendered page and the selected browser theme remain under GitHub/user control.

## Compatibility and accessibility

- Important text, project status, stack labels and links remain actual README content.
- Each meaningful image has descriptive alt text.
- No external image host, custom CSS, JavaScript, SVG script or foreignObject is required.
- GIFs use continuous loops and restrained low-frequency scanning; no strobing or flashing is intended.
- GitHub profile README tables do not provide a guaranteed mobile one-column breakpoint. The two-column layout must be checked on the live profile; narrow rendering remains a platform limitation if GitHub keeps table columns side-by-side.

## Validation and performance

The validator locks the approved Hero; resolves local references; checks SVG safety; verifies expected card assets, image dimensions, GIF animation/loop/timing and per-file/total asset budgets. It does not enforce the obsolete exact 24-frame/220 ms rule or old image/table counts. Public secret scanning and the RSS/Atom updater tests remain in CI.

Current asset budgets: 300 KiB per static raster, 350 KiB per GIF, 3 MiB total under `assets/`. These are repository safeguards sized for the intended 600×260 project animations and 640×300 focus cards, not claims about browser load time.
